# 文章发布自动化

37 篇文章已经排好上线日期（`schedule.json`）。这个文件夹把每周发布变成**一条命令**，也可以让你的 Mac 每周自动执行。

## 它会做什么

`publish.sh` 每次执行：

1. 从 GitHub 拿最新的文章。
2. 只生成**上线日期已到**的文章，转成完整的 HTML 页面：标题、meta description、canonical、结构化数据（上线日期自动改成实际那一周）都放好了。
3. 指向**还没上线**文章的链接，自动变成普通文字，所以永远不会有坏链接。每周重新生成时，总指南和问答大全会自动加上新文章的链接。
4. `hold.txt` 里的文章**先不发**（见下面）。
5. 用结构化数据检查脚本检查新页面和整个网站文件夹。
6. 把页面复制到网站的 `insights/` 文件夹，加上 `sitemap-insights.xml`；如果设置了部署命令，就直接部署。

你自己做的页面不会被覆盖：如果 `insights/` 里已经有同名、但不是脚本生成的文件，脚本会跳过它并提示你。

## 第一次设置（大约 10 分钟）

1. 在 Mac 上把仓库下载下来（只需要一次）：
   ```
   git clone https://github.com/rsphotographysg-sudo/seo-data.git ~/seo-data
   ```
2. 打开 `~/seo-data/publishing/publish.sh`，填最上面两行：
   - `SITE_PUBLIC_DIR`：Cloudflare Pages 发布的那个网站文件夹（里面有首页 `index.html` 的那个）。
   - `DEPLOY_CMD`：你平时的部署命令，例如 `npx wrangler pages deploy . --project-name=你的项目名`。不填的话，脚本只复制文件，你自己部署。
3. 先试一次：
   ```
   ~/seo-data/publishing/publish.sh
   ```
   打开网站的 `/insights/annual-dinner-photography-singapore` 看看。

**注意：** 生成的是独立页面，用简单干净的样式，没有你网站的导航栏和页脚。如果你的网站有统一模板，用 `dist/fragments/` 里的两个文件：`<slug>.head.html` 放进 `<head>`，`<slug>.body.html` 放进正文位置。

## 每周自动执行（可选）

让 Mac 每周二早上 9 点自动执行：

1. 打开 `publishing/com.rsphotography.publish-insights.plist`，把 `REPO_PATH` 换成仓库的完整路径（例如 `/Users/ricky/seo-data`）。
2. 在终端执行：
   ```
   cp ~/seo-data/publishing/com.rsphotography.publish-insights.plist ~/Library/LaunchAgents/
   launchctl load ~/Library/LaunchAgents/com.rsphotography.publish-insights.plist
   ```
3. 执行记录在 `/tmp/rs-publish-insights.log`。Mac 那时要开着（睡眠的话，醒来后会补跑）。

要停掉：`launchctl unload ~/Library/LaunchAgents/com.rsphotography.publish-insights.plist`。

## 暂缓发布的文章（hold.txt）

这几篇有需要你先确认的内容，确认前**不会发布**，其他文章也不会链接到它们：

| 文章 | 要先确认 |
|---|---|
| 如何挑选摄影师 | 第 10 题提到公众责任险：先买好保险 |
| 企业宣传片 | “很多项目在 S$10,000–20,000”：确认愿意公开 |
| 跑步赛 | 提到按号码布搜索的相册：确认能提供 |
| 科技会议 | 点名 Asia Tech x Singapore 和 HR Tech Asia：确认可以公开 |
| 版权和使用权 | 法律内容：在 SSO 核对《2021 年版权法》或问律师 |
| 大使馆 / 外交活动 | 文中写“我们拍外交活动”：确认你们拍过 |

确认后，把 `hold.txt` 里那一行删掉，下次执行就会发布。也可以把其他文章加进去暂缓。

## 每次发布后（自动化做不到的部分）

- Search Console → 网址检查 → 输入新文章网址 → 请求编入索引。
- 在 LinkedIn 分享一次。

## 以后加新文章

把文章放进 `articles/`，在 `schedule.json` 加一行 `"slug": "上线那周的日期"`。

## 外部链接

文章里的 `[EXTERNAL LINK: …]` 已在 `build_articles.py` 里对应到官方网站（SSO、WSH Council、PDPC、气象局）。没有可靠网址的（Airtasker、MOF 那篇）直接去掉。联系页如果不是 `/contact`，改 `build_articles.py` 里的 `EXISTING_PATHS`。
