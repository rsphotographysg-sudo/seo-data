# rsphotographysg.com 结构化数据修复指南（2026 年 10 月 15 日）

Google Search Console 在 7 月发来三封通知。下面每个问题都写了：原因、怎么改、改好的样子。

网站源代码在你的 Mac 上（Cloudflare Pages 那个项目），不在这次的云端环境里，所以我没法直接改网站。按下面三步做，大约 30 分钟。

## 第 1 步：在网站文件夹里跑检查脚本

```bash
python3 fix_structured_data.py ~/你的网站文件夹
```

它会列出每个有问题的文件和属性。再跑一次加 `--fix`，会自动把视频的 uploadDate 改成带新加坡时区的格式：

```bash
python3 fix_structured_data.py ~/你的网站文件夹 --fix
```

重复属性和活动字段需要你决定保留哪个值，脚本只报告，不会乱改。

## 第 2 步：按问题修改

### 问题 1（严重）：无法解析的结构化数据 — “Duplicate unique property”

**原因：** 某个 JSON-LD 对象里同一个属性写了两次，例如两个 `"name"`、两个 `"@id"` 或两个 `"@type"`。Google 遇到这种情况会整段不读，所以这一项最优先。

**怎么改：** 脚本会指出是哪个文件、哪个属性。保留一个，删掉另一个。如果两个值都想要，就改成列表：

```json
// 错误
{ "@type": "LocalBusiness", "name": "RS Photography", "name": "RS Photography Singapore" }

// 正确
{ "@type": "LocalBusiness", "name": "RS Photography", "alternateName": "RS Photography Singapore" }
```

### 问题 2：Events（活动）缺少 organizer.url、endDate、offers

**先判断这些活动是什么：**

- **如果是你拍过的客户活动**（案例、作品集页面）：这些活动不是公众可以报名参加的，Google 的活动规则不允许用 Event 标记。**最好的做法是删掉 Event 标记**，改用下面的 Article 写法。这样问题会直接消失，也不会被当成误导性标记。
- **如果是 RS 自己办、公众可以报名的活动**（例如摄影工作坊）：保留 Event，把三个字段补上。

**案例页面的写法（推荐）：**

```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "SAF Congress 2026 活动摄影案例",
  "datePublished": "2026-07-15T09:00:00+08:00",
  "author": { "@type": "Organization", "name": "RS Photography", "url": "https://rsphotographysg.com" },
  "publisher": { "@type": "Organization", "name": "RS Photography", "url": "https://rsphotographysg.com" },
  "about": { "@type": "Thing", "name": "Corporate event photography in Singapore" }
}
```

**真正的公开活动的写法：**

```json
{
  "@context": "https://schema.org",
  "@type": "Event",
  "name": "活动名称",
  "startDate": "2026-11-20T09:00:00+08:00",
  "endDate": "2026-11-20T17:00:00+08:00",
  "eventStatus": "https://schema.org/EventScheduled",
  "eventAttendanceMode": "https://schema.org/OfflineEventAttendanceMode",
  "location": { "@type": "Place", "name": "场地名称", "address": { "@type": "PostalAddress", "addressLocality": "Singapore", "addressCountry": "SG" } },
  "organizer": { "@type": "Organization", "name": "RS Photography", "url": "https://rsphotographysg.com" },
  "offers": { "@type": "Offer", "url": "https://rsphotographysg.com/报名页面", "price": "0", "priceCurrency": "SGD", "availability": "https://schema.org/InStock", "validFrom": "2026-10-15T00:00:00+08:00" }
}
```

### 问题 3：Videos（视频）的 uploadDate 没有时区 / 格式不对

**原因：** uploadDate 写成了 `2026-05-07` 或 `2026-05-07 09:30` 这类格式。Google 要求完整的 ISO 8601 时间，并带时区。

**怎么改：** 跑 `--fix` 会自动改。手动改的话照这个格式：

```json
"uploadDate": "2026-05-07T09:30:00+08:00"
```

视频对象最好同时有 `name`、`description`、`thumbnailUrl`，脚本也会检查这几项。

## 第 3 步：上线并请 Google 验证

1. 再跑一次检查脚本（不加 `--fix`），确认三类问题都是 0。
2. 部署网站（你的 Cloudflare Pages 部署命令）。
3. 用 Google 的 Rich Results Test（search.google.com/test/rich-results）测一个改过的页面。
4. 打开 Search Console：
   - “增强功能 → 活动” → 点问题 → **验证修复**
   - “增强功能 → 视频” → 点问题 → **验证修复**
   - “增强功能 → 无法解析的结构化数据” → **验证修复**
5. Google 通常在几天到两周内发邮件告诉你结果。收到后告诉我，我会更新报告。

## 注意

- 不要删除首页的 `google-site-verification` meta 标签。
- 我没能看到线上网站，所以不知道具体是哪几个页面。Search Console 的问题页面会列出受影响的网址，可以对照脚本的结果。
